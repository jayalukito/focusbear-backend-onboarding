# Git Knowledge & Reflection
**Role:** Developer Intern

## 1. Have you used Git before? If so, in what context?
Yes, I have used Git extensively in both my academic projects at Swinburne University and during my professional internship as a Front-End Software Engineer at Omni (IT Consulting). For example, I used Git to version control my custom Point of Sale (POS) application built with C# and SplashKit, and more recently, for collaborating on the Bengali-language smishing detector project involving Machine Learning models and Pytorch. I regularly use branching to isolate feature development and PRs for code reviews.

## 2. Which Git client (if any) did you choose? Why?
I use a hybrid approach: I rely heavily on the **built-in Git integration in Visual Studio Code (VS Code)** for everyday tasks. The visual Source Control view makes it incredibly easy to stage specific files, review side-by-side diffs, and manage branches without leaving my editor. However, I also use the **Git Command Line Interface (CLI)** for more complex operations, such as resolving tricky merge conflicts or running interactive rebases (`git rebase -i`), because it provides granular control and helps me understand what is happening under the hood.

## 3. What was the most interesting thing you learned about Git today?
The most interesting thing I learned today is how seamlessly VS Code handles repository initialization and remote publishing directly from the Command Palette or the Source Control UI, completely abstracting away the need to manually configure remote URLs via the terminal. It is fascinating how the Source Control Graph and diff editor visually represent commit histories and file changes side-by-side, which dramatically speeds up my workflow when reviewing code.
